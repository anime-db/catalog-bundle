# Рекомендации по улучшению кодовой базы

> Рекомендации по повышению поддерживаемости и безопасности. Конкретные баги — в [BUGS.md](BUGS.md); сводка — в [AUDIT.md](AUDIT.md).
> См. также: [PROJECT.md](PROJECT.md) · [TECHNICAL.md](TECHNICAL.md)

Каждая рекомендация помечена ожидаемым эффектом: 🔒 безопасность · 🧰 поддерживаемость · ⚡ производительность · 🧪 тестируемость.

## Безопасность

### R-01 🔒 CSRF-защита деструктивных операций (приоритет №1)
Все state-changing действия, доступные по GET (`item_delete`, `storage_delete`, `storage_scan`, `update_execute` — см. [AUDIT.md](AUDIT.md#находки-по-безопасности)), перевести на **POST + CSRF-токен**. Минимально — добавить проверку HTTP-метода и `$this->isCsrfTokenValid()`. Это закрывает доминирующий вектор CSRF→RCE даже в localhost-модели.

### R-02 🔒 Whitelist composer-пакетов
`UpdateController::indexAction` (`src/Controller/UpdateController.php:54`) — перед `addPackage`/`removePackage` валидировать имя пакета по строгому шаблону (например, только `anime-db/*` или `vendor/animedb-plugin-*`) и версию по semver-regex. Никогда не передавать сырой POST в манипулятор пакетов.

### R-03 🔒 `escapeshellarg` на аргументы команд
`ScanExecutor::export()` (`src/Service/Storage/ScanExecutor.php:72`) и `UpdateController::executeAction` (`:131`) — обернуть каждый интерполируемый аргумент в `escapeshellarg()`. Сейчас спасает только то, что id — целое; защита по конструкции отсутствует.

### R-04 🔒 Whitelist внутри `Builder::sort()`
`src/Service/Item/Search/Selector/Builder.php:307` — продублировать проверку колонки/направления внутри метода, не полагаясь на внешний `Manager`. Defense-in-depth против будущих прямых вызовов.

### R-05 🔒 Ограничить путь хранилища
Валидировать `Storage::$path` (например, запрещать корни/системные каталоги или требовать подтверждения), чтобы скан не мог перечислять произвольные части ФС. Рассмотреть confinement к домашней папке пользователя по умолчанию.

### R-06 🔒 Единые права файлов-маркеров
Привести запись `.storage` к единым правам (0644) и единому хелперу (см. [B-12](BUGS.md#сканирование--console)); убрать mode 0666 в `Entity/Listener/Storage.php:53`.

## Система плагинов

### R-07 🧰 Единый контракт ошибок
`Chain::getPlugin()` (`src/Plugin/Chain.php:45`) — определиться: либо бросать исключение на неизвестное имя, либо везде возвращать null и проверять у вызывающих. Сейчас несогласованно (null vs `LogicException` в `Filler`). Добавить guard в `Search\Chain::getDafeultPlugin()`.

### R-08 🧰 Детектировать коллизии имён
`Chain::addPlugin()` (`Chain.php:34`) — бросать исключение при повторном `getName()` вместо тихого перетирания.

### R-09 🧰 Приоритеты вместо алфавита
Порядок плагинов сейчас чисто алфавитный (`ksort`). Перейти на стандартный Symfony-механизм `priority` в тегах; перенести сортировку из `addPlugin` в ленивую (`getPlugins()`), убрав двойной `ksort` на каждой вставке ([B-27](BUGS.md#система-плагинов)).

### R-10 🧰 Логировать проглоченные исключения
`Search::getCatalogItem()` (`src/Plugin/Fill/Search/Search.php:130`) — как минимум логировать через инжектированный `LoggerInterface`, а не `catch (\Exception $e) {}`.

### R-11 🧰 Разгрузить `FillerInterface`
«Толстый» интерфейс смешивает домен/форму/DI/роутинг. Вынести `setRouter` из контракта (использовать DI setter-инъекцию вне интерфейса); разбить на более узкие интерфейсы. Убрать `@deprecated` с `Plugin` либо удалить базовые классы — текущая ситуация (все наследуют deprecated) неактуализируема ([B-28](BUGS.md#система-плагинов)).

## Доменная модель

### R-12 🧰 Синхронизировать маппинг со схемой
Привести nullable-флаги маппинга в соответствие миграциям: `date_premiere` → `nullable=true` ([B-14](BUGS.md#доменная-модель)). Провести ревизию всех nullable-полей против реальной SQLite-схемы.

### R-13 🧰 Инкапсуляция коллекций и дат
Возвращать неизменяемые представления коллекций (или клоны) из геттеров `Item`/`Storage` ([B-19](BUGS.md#доменная-модель)); клонировать `\DateTime` в `Storage`-геттерах как уже сделано в `Item`.

### R-14 🧰 Явные cascade / ON DELETE
Определить поведение при удалении справочников (Storage/Country/Type/Studio): либо `ON DELETE SET NULL`/`RESTRICT` на уровне БД, либо явная проверка в сервисе ([B-20](BUGS.md#доменная-модель)).

### R-15 🧰 Вынести запись из репозитория
`Repository\Label::updateListLabels()` с `flush()` (`src/Repository/Label.php:25`) — перенести в доменный сервис; репозитории держать read-oriented.

### R-16 ⚡ Пагинация через Doctrine Paginator
`Repository\Item::getList()` и `findDuplicate()` (O(n²) слияние) — рассмотреть `Doctrine\ORM\Tools\Pagination\Paginator` и оптимизацию дедупа.

## Console / Сканирование

### R-17 🧰 Корректный сигнал завершения скана
`Progress\Export::__destruct()` (`src/Console/Progress/Export.php:88`) не должен безусловно писать `100%`. Писать прогресс только в `finish()`; при ошибке оставлять последнее значение или писать маркер сбоя ([B-10](BUGS.md#сканирование--console)).

### R-18 🧰 Устойчивый парсинг завершения
Заменить строковый поиск `Fatal error:`/`Time:` ([TECHNICAL.md](TECHNICAL.md#признак-завершения)) на явный exit-маркер, записываемый командой (например, последняя строка `__SCAN_DONE__`/`__SCAN_FAILED__`). Это устранит ложные срабатывания и баг `!=`/`!==` ([B-05](BUGS.md#контроллеры)).

## Frontend

### R-19 🧰 Байтовый offset в опросе лога
`progress_log.js:37` — согласовать единицу offset с серверным `mb_substr`/байтами ([B-29](BUGS.md#frontend-js)). Передавать серверный offset обратно как есть, не вычислять на клиенте через `.length`.

### R-20 🧰 Устранить утечки глобалов
Добавить `var`/`let` во всех `if (x = ...)` ([B-32](BUGS.md#frontend-js)); включить strict-mode и линтер (ESLint) в сборку.

### R-21 🧰 Политика артефактов сборки
Либо коммитить и JS, и CSS dist, либо не коммитить ничего и собирать на деплое. Сейчас JS закоммичен, CSS — нет (drift-риск). Добавить CI-проверку «dist соответствует src».

## Зависимости и инфраструктура

### R-22 🔴 План модернизации стека
Стек полностью EOL ([AUDIT.md](AUDIT.md#состояние-зависимостей-критично)). Долгосрочно: поднять PHP до поддерживаемой версии, Symfony/Twig/Doctrine — до LTS, jQuery 1.x → 3.x (закрывает XSS CVE), PHPUnit 4 → актуальный. Это крупная работа; как минимум — зафиксировать риск и не добавлять нового кода под 5.4-идиомы без необходимости.

### R-23 🧰 Починить/заменить CI
Travis-ci.org, Coveralls, Scrutinizer, SensioLabs Insight — мёртвые/legacy. Перевести на GitHub Actions; обновить/убрать бейджи в README. Заменить заброшенный `satooshi/php-coveralls` на `php-coveralls/php-coveralls` или нативное покрытие.

## Тесты

### R-24 🧪 Покрыть контроллеры и команды
Нет ни одного теста на `Controller` (11 шт.), `Command`, `Menu`, `Repository` ([TECHNICAL.md](TECHNICAL.md#тесты-карта-покрытия)). Приоритет — функциональные тесты на scan/install/refill AJAX-потоки (то, что опрашивает frontend) и на `ScanStoragesCommand`.

### R-25 🧪 Убрать хрупкие позиционные моки
`ScanExecutorTest:71-78` (`$this->at(2)/at(3)`) — заменить на проверку аргументов без жёсткой привязки к порядку ([B-36](BUGS.md#тесты)).
